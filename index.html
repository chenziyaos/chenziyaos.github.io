Weft

让模型读到的上下文看得见、改得动。

无限画布上的对话，连线就是上下文

每次问答是画布上的一个节点；节点能看到的，恰好是沿箭头流进来的内容。剪掉一条线，下一次回答就变了。

  • 追问与分支：从任意节点继续，或只针对回答里选中的一段开分支，兄弟分支互相看不见。
  • 发送前看清请求：输入框上方显示将发送多少 token、多少条消息，可以展开成完整请求。
  • 改上下文就是改连线：剪断、改接、插入一步，再按依赖顺序重放受影响的节点。
  • 接终端 agent：Claude Code / Codex 会话可以打开成画布镜像来修剪、分支，原会话文件不被改写。
# 不 clone 也能用：npm 包带画布、代理和 weft 命令
npm install -g weft-canvas
weft serve   # http://localhost:3001

ngx_stream_upstream_check_module

给 nginx stream（四层 TCP/UDP 代理）加主动健康检查：按间隔探测 upstream 里的每个 server，连续失败 fall 次摘除、连续成功 rise 次恢复；支持 TCP、UDP、HTTP 三种探测，带一个输出 HTML / CSV / JSON 的状态页。开源 nginx 的 stream 只有被动检查。

核心补丁按版本分三份，覆盖 1.24–1.31（1.27 没有补丁）；CI 在 1.22–1.31 的六个版本上编译并跑集成测试。

onssh

在浏览器里登录 Linux 服务器的 SSH 终端：Python 3（tornado + paramiko）加 xterm.js，能跑 vim、top，窗口大小随浏览器变化。带主机密钥校验和目标白名单，默认只监听本机。

uv run onssh   # http://127.0.0.1:8000/，需要 Python ≥ 3.10

不是堡垒机：只支持密码登录，没有用户体系、审计和录屏。

使用前要知道的

  • zero-to-* 是学习用的配套代码，不是库。模拟器复现的是引擎主干里的关键账本，结果要和真实日志对账才算数。四个引擎和 GPU 仓库的 README 写了版本基线（具体到 commit），换了版本数字可能对不上。
  • zero-to-llm 后半部分的案例读数是假设读数。准确率、时延、成本这些案例数字是示意用的，不是实测；能复算的是代码输出和公式推导，正文里都标明了。这个仓库没有 Colab notebook。
  • Colab notebook 只放 CPU 能跑的命令。要 GPU、模型文件或运行中服务的命令没有放进去，要自己找机器跑。
  • 部分大模型章节还没有 GPU 实测。例如 llama.cpp 系列的双模型部署层只做启动前的字节推算，实测前标为 pending_gpu_measurement；以各章正文的说明为准。
  • Weft 的画布数据存在浏览器 IndexedDB 里，没有同步也没有账号，用「导出备份（.json）」备份。桌面安装包未签名，限制和排障见它的 README。
  • 在线阅读版由 MkDocs 从各仓库的 Markdown 生成，推送到主分支后自动更新，内容和 GitHub 上的原稿一致；只有用到公式的系列会从 jsDelivr 加载 KaTeX。
  • nginx-devops 的实验只在 macOS arm64 上跑过。Linux 上事件模块是 epoll，debug 日志和页大小相关的数字会不同；图从 spec 生成，生成引擎没有公开。
